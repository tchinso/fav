# fav.ju.mp 백업

[fav.ju.mp](https://fav.ju.mp/)의 HTML, 이미지, 폰트, 스크립트를 원래 디렉터리 구조로 보관합니다. 백업 사이트는 [tchinso.github.io/fav](https://tchinso.github.io/fav/)에서 볼 수 있습니다.

GitHub Actions의 **Back up fav.ju.mp** 워크플로가 **매주 월요일 오전 03:17 한국시간(KST)**에 실행됩니다. UTC cron은 `17 18 * * 0`이며 GitHub 실행 대기열에 따라 실제 시작은 지연될 수 있습니다.

다운로드한 파일은 임시 디렉터리에서 검증한 뒤 저장소에 반영합니다. 사이트와 리소스 요청에는 시간 제한과 재시도를 적용하고, 전체 백업도 최대 3회 시도합니다. 서버 장애, 오류 페이지, 누락된 리소스가 확인되면 작업이 실패하며 이전 정상 백업을 유지합니다. `backup-manifest.json`은 마지막 성공 시각과 파일별 SHA-256을 기록합니다. 매번 성공 기록을 커밋하므로 콘텐츠가 같아도 저장소에 활동이 남습니다.

`index.html`은 백업된 로컬 파일을 참조하도록 링크가 변환된 페이지입니다. `assets/`, `cdn-cgi/` 등의 파일을 함께 보관하고, 링크 변환 전 원본 HTML도 `index.html.orig`로 남깁니다. 북마크가 가리키는 외부 사이트 전체를 다운로드하지는 않습니다. 동적으로 로드하는 외부 상담 위젯 등 외부 서비스 기능은 원래 서비스 연결이 필요합니다. `search-list.json`은 별도 데이터이므로 자동으로 변경하지 않습니다.

저장소에는 **최신 백업 한 커밋만** 남도록, 성공할 때마다 부모 없는 새 커밋으로 `main`을 교체합니다. 다운로드 중 다른 커밋이 올라오면 `--force-with-lease`가 덮어쓰기를 거부합니다. GitHub의 이전 Git 객체 정리는 서버에서 처리하므로 저장 공간 감소가 즉시 표시되지는 않을 수 있습니다. 각 실행의 **Artifacts**에는 전체 파일을 담은 `fav-site-…` ZIP을 **7일** 동안 보관합니다. Actions → **Back up fav.ju.mp** → **Run workflow**로 수동 실행할 수 있습니다.

로컬에서 확인하려면 저장소 루트에서 `python -m http.server 8000`을 실행한 뒤 `http://localhost:8000`을 여세요. ZIP 백업도 압축을 풀고 같은 방법으로 열 수 있습니다.

워크플로는 기본 제공 `GITHUB_TOKEN`의 `contents: write`, `pages: write` 권한을 사용하며 별도의 토큰이나 시크릿이 필요하지 않습니다. 검증된 백업을 커밋한 뒤 기존 GitHub Pages 빌드를 요청해 대체 사이트도 갱신합니다. 저장소가 60일 이상 활동이 없으면 GitHub에서 예약 작업을 비활성화할 수 있으므로 장기간 백업이 실패한 뒤에는 Actions에서 활성화 상태를 확인하세요.

Cloudflare Pages의 Git 연동에서도 이 저장소의 `main`을 배포 브랜치로 사용하면 새 백업 푸시가 자동 배포를 시작합니다. 기존과 같이 루트의 `index.html`을 사용하므로 정적 HTML 배포 설정을 유지할 수 있습니다. 별도 Cloudflare API 토큰은 필요하지 않습니다.
